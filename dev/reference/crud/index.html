Generated CRUD API¶

Updated November 20, 2026 3 min read

The CRUD guide explains action generation, access policies, ownership, schema requirements and route replacement.

hinoki.resources.crud ¶

crud(
    model: type[Model],
    *,
    path: str,
    read: type[Schema],
    create: type[Schema] | None = None,
    update: type[Schema] | None = None,
    delete: bool = False,
    access: Access | CrudAccess | None = None,
    public_writes: bool = False,
    owner: str = "",
    identity_key: Callable[[Any], Any] = attrgetter("id"),
    assign: Mapping[str, Callable[[Any], Any]]
    | None = None,
    pagination: Pagination = PageNumberPagination(),
    filters: type[FilterSet] | None = None,
    omit: tuple[str, ...] = (),
    name: str | None = None,
    cors: Cors | None = None,
    include_in_schema: bool | Mapping[str, bool] = True,
    tags: Sequence[str] = (),
    deprecated: bool | date = False,
) -> CrudDeclaration

Declare generated CRUD for model.

app.include(crud(...)) mounts the generated actions; @crud(...) on a class adds the hooks (get_queryset, to_schema, written_queryset, store, change, remove) and handwritten actions. A single Access protects every action; CrudAccess sets them apart. name= names the generated class ("ArchiveCrud") or its module and class ("notes.apps.archive.ArchiveCrud") that rules and MCP patterns match. cors=http.Cors(...) gives every generated action that CORS policy instead of the application's. filters= takes a FilterSet subclass: the list then accepts the filters, ordering and search it declares. include_in_schema=False leaves every generated action out of the OpenAPI document; include_in_schema={"delete": False} leaves out only the named actions. tags and deprecated apply to every action. Left-out actions are still served and protected by their access.
