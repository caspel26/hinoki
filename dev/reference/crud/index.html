Generated CRUD API¶

The CRUD guide explains action generation, access policies, ownership, schema requirements and route replacement.

hinoki.crud.Resource dataclass ¶

What to generate for model.

  • read is the output schema; create / update (PATCH, fields left UNSET are untouched) enable those actions; deletable enables delete.
  • access protects the write actions, read_access the reads.
  • owner names a column that holds the owner: it is assigned from the caller on create and must match the caller on update and delete. identity_key extracts the owner value from Caller.user.
  • assign maps other columns to a function of the caller's identity, applied on create; clients cannot send them.
  • queryset supplies the base query (e.g. with select_related) and output converts a row to the read schema when it is not a plain copy.

owner_of ¶

owner_of(principal: Any) -> Any

The caller's owner value; a caller without one may change nothing, or None would match every ownerless row.

scope ¶

scope(key: Any, principal: Any) -> QuerySet[Any]

The rows a change may touch: the base query, the primary key and the owner, all in the UPDATE/DELETE itself, so a row that was hidden or changed hands meanwhile is untouched.

written async ¶

written(key: Any) -> Any

Read back a row the caller just wrote. It may now be outside the base query (archived, unpublished); the writer still sees the result.

guard async ¶

guard(key: Any, principal: Any) -> None

404 for a row outside the base query (or missing), 403 when somebody else owns it. Rows the base query hides look the same as missing ones.

refused async ¶

refused(key: Any) -> Forbidden

A write matched no row: 404 if the row is gone or hidden by now, otherwise the owner changed under the caller.
