Generated CRUD API¶

Updated November 24, 2026 7 min read

The CRUD guide explains action generation, access policies, ownership, schema requirements and route replacement.

hinoki.resources.crud ¶

crud(
    model: type[Model],
    *,
    path: str,
    read: type[Schema],
    create: type[Schema] | None = None,
    update: type[Schema] | None = None,
    delete: bool = False,
    access: Access | CrudAccess | None = None,
    public_writes: bool = False,
    owner: str = "",
    identity_key: Callable[[Any], Any] = attrgetter("id"),
    assign: Mapping[str, Callable[[Any], Any]]
    | None = None,
    pagination: Pagination = PageNumberPagination(),
    filters: type[FilterSet] | None = None,
    omit: tuple[str, ...] = (),
    name: str | None = None,
    cors: Cors | None = None,
    include_in_schema: bool | Mapping[str, bool] = True,
    tags: Sequence[str] = (),
    deprecated: bool | date = False,
    links: Mapping[str, Callable[[Any], QuerySet[Any]]]
    | None = None,
) -> CrudDeclaration

Declare generated CRUD for model.

app.include(crud(...)) mounts the generated actions; @crud(...) on a class adds the hooks (get_queryset, to_schema, written_queryset, store, change, remove) and handwritten actions. A single Access protects every action; CrudAccess sets them apart. name= names the generated class ("ArchiveCrud") or its module and class ("notes.apps.archive.ArchiveCrud") that rules and MCP patterns match. cors=http.Cors(...) gives every generated action that CORS policy instead of the application's. filters= takes a FilterSet subclass: the list then accepts the filters, ordering and search it declares. include_in_schema=False leaves every generated action out of the OpenAPI document; include_in_schema={"delete": False} leaves out only the named actions. tags and deprecated apply to every action. Left-out actions are still served and protected by their access. links={"tags": all_rows(Tag)} scopes the targets a many-to-many ids field (tag_ids) may link and show: a function of the caller's user that returns a QuerySet of the target. Every ids field needs an entry.

Filters¶

A FilterSet declares what a client may ask of a generated list and is passed as filters=; see filter, order and search the list. Declare each field as Eq[T], In[T] or Range[T] (type aliases of hinoki.filters) and add a Search(...) and an ordering tuple. A Range field reads as a Bounds.

hinoki.filters.FilterSet ¶

FilterSet(parsed: FilterParsed)

Base class of a list's declared filters. Subclass it and annotate each filter; use it on its own with InvoiceFilters.parse(query).

Instances hold what the client sent: params.paid is False or None (not sent), params.status a list or None, params.issued a Bounds or None, params.search_term the text or None and params.order the client's ordering as column names, - for descending. params.is_null("closed") answers a closed.null filter, declared by a T | None type argument.

Row scoping¶

hinoki.resources.all_rows ¶

all_rows(model: type[T]) -> Callable[[object], QuerySet[T]]

A links= entry that lets the caller link every row of model: the explicit choice for targets that are not private to anyone.

hinoki.resources.own_rows ¶

own_rows(
    model: type[T], column: str
) -> Callable[[object], QuerySet[T]]

A links= entry that lets the caller link and see only the rows of model whose text column holds the caller's id (Caller.id). It needs access on every action, and generated CRUD keeps it on the native lane.

hinoki.resources.from_user ¶

from_user(attr: str) -> UserAttr

Extract attr (or a dotted attribute path) from Caller.user for crud(..., assign={...}) or identity_key=....
