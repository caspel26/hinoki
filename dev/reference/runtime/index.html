Events¶

The events guide explains the two moments a handler runs in. A handler collection is listed on the application, or in an app's events entry of hinoki.toml.

hinoki.events.Handlers ¶

Handlers(name: str = '')

A collection of event handlers, listed on the application to take effect.

@handlers.in_transaction(Event) and @handlers.after_commit(Event) register the decorated function, which is returned unchanged so a test can call it directly. The event type is Event or, for events about one class, Event[Note]; the handler's parameter must be annotated with the same type. Registration order is execution order.

name instance-attribute ¶

name = name

registrations property ¶

registrations: tuple[Registration, ...]

in_transaction ¶

in_transaction(
    kind: type[E],
) -> Callable[
    [Callable[[E], Awaitable[None]]],
    Callable[[E], Awaitable[None]],
]

Run inside the transaction of the write that emitted the event. An exception or a timeout rolls the write back and reaches its caller.

after_commit ¶

after_commit(
    kind: type[E],
) -> Callable[
    [Callable[[E], Awaitable[None] | None]],
    Callable[[E], Awaitable[None] | None],
]

Run after the outermost transaction commits (at once when none is open). A failure is logged and counted; it cancels nothing.

hinoki.events.Created dataclass ¶

Created(subject: type[M], instance: M)

A model row was inserted by insert (acreate, asave of a new instance, abulk_create, generated CRUD create). instance is the stored instance.

hinoki.events.Updated dataclass ¶

Updated(
    subject: type[M], instance: M, changed: tuple[str, ...]
)

A model instance was saved with changes (asave, aupdate_from, abulk_update, generated CRUD update). changed names the columns that differed from the stored row before the write.

hinoki.events.Deleted dataclass ¶

Deleted(subject: type[M], count: int)

A DELETE statement removed count rows of the model (adelete, abulk_delete, generated CRUD delete). No key or row is loaded.

hinoki.events.emit async ¶

emit(event: object) -> None

Emit event on the current worker's bus.

hinoki.events.listener ¶

listener(
    kind: type, subject: type | None = None
) -> EventBus | None

The current bus when a write of subject (or, for an event with no subject, any emitter) must emit kind, else None: the guard of the emitting code paths (one context-variable read when no application bus is current).

hinoki.events.Linked dataclass ¶

Linked(
    subject: type[M],
    relation: str,
    key: object,
    targets: tuple[object, ...],
)

Links were added to a many-to-many relation (add or set of a LinkSet). subject is the model that declares relation; key is the primary key of the owner that was written (the declaring model, or the target when writing from the reverse side) and targets the keys of the rows now linked to it, in ascending order. Emitted only when something was added; needs after_commit handlers.

hinoki.events.Unlinked dataclass ¶

Unlinked(
    subject: type[M],
    relation: str,
    key: object,
    targets: tuple[object, ...],
)

Links were removed from a many-to-many relation (remove or set of a LinkSet); the fields are those of Linked. Deleting a row that has links removes them without this event, like Deleted. Emitted only when something was removed; needs after_commit handlers.

hinoki.events.AuthRejected dataclass ¶

AuthRejected(reason: str, route: str, method: str)

A route's access policy refused a request (HTTP 401 or 403).

reason is "missing" (no credentials), "invalid" (credentials the provider rejected) or "forbidden" (a caller without a required permission). route is the path template (/notes/{note_id}), never the requested path; method is the HTTP method, or WEBSOCKET. The payload holds no credential, caller, address or query string. Delivered through EventBus.notify, so it needs after_commit handlers.

hinoki.events.RateLimited dataclass ¶

RateLimited(
    policy: str, route: str, method: str, retry_after: int
)

A route's rate-limit policy refused a request (HTTP 429).

policy is the class name of the route's policy, retry_after the whole seconds the client was told to wait. The payload holds no key, caller, address or path. Delivered through EventBus.notify, so it needs after_commit handlers.
