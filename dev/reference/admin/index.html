hinoki.admin.ModelAdmin ¶

ModelAdmin()

How one model appears in the admin. Subclass and override what you need.

  • queryset scopes every list, lookup, update and delete (it is part of the SQL statement); can gates view, add, change and delete for a model or a row. Row visibility belongs in queryset.
  • save and remove are the single places that write, so an application can run a domain command there instead of writing around its rules. assign columns are set by the server on creation and are not form fields; readonly columns are shown but never accepted; exclude columns are neither shown nor accepted.
  • After a default write the row must still be inside queryset; otherwise the write is rolled back.

hinoki.admin.users.limits.LoginWindow ¶

LoginWindow(
    limit: int = 10,
    window: int = 60,
    clock: Callable[[], float] = time.monotonic,
)

At most limit attempts per window seconds from one address.

Requests with no known client address (a Unix socket, a proxy that is not listed in server.trusted_proxies) share one window UNKNOWN_FACTOR times as large, so they cannot lock everyone out of sign-in with a few requests.

make_room(now: float) -> None

hinoki.admin.users.limits.DatabaseLoginWindow ¶

DatabaseLoginWindow(
    limit: int = 10,
    window: int = 60,
    clock: Callable[[], datetime] = utc_now,
    timeout: float = 0.5,
)

Bases: RateLimit

At most limit attempts per window seconds from one address on one route, counted by the shared RateLimit in the hinoki_admin_rate_limits table, so every worker and every host counts together and a restart keeps it.

Clients are stored as a SHA-256 digest, never as an address. Requests with no known address share one bucket UNKNOWN_FACTOR times as large. A storage failure refuses the attempt (503).
