hinoki.settings.Settings dataclass ¶

Settings()

Base class: subclasses are keyword-only frozen dataclasses.

load classmethod ¶

load(
    *,
    prefix: str | None = None,
    env: Mapping[str, str] | None = None,
    dotenv: str | PathLike[str] | None = None,
    toml: str | PathLike[str] | None = None,
    overrides: Mapping[str, Any] | None = None,
    strict: bool = True,
) -> Self

Build the settings. Precedence: overrides, env (default: the process environment), dotenv, TOML file, and field defaults.

strict (default) makes a variable that starts with prefix and looks like a setting but names no field an error, which catches typos; other variables that only share the prefix are ignored. With an empty prefix nothing can be told apart from the rest of the environment, so no typo check happens.

prefix, dotenv and toml default to what the class declared.

hinoki.settings.ServerSettings dataclass ¶

ServerSettings()

Bases: Settings

How hinoki serve and dev run the application. serve applies these; they do nothing when another runner starts the app.

server picks Kiso, Hinoki's Rust server (the default), or Granian. interface is how the server calls the target: asgi (a Hinoki application) or wsgi (a WSGI callable, such as a WSGIAdapter); the --interface flag overrides it. access_log prints one line per request on either server; unset, hinoki dev logs and hinoki serve does not, and True or False decides for both. access_log_format (Rust server only: pretty, plain, json or logger) chooses how a line looks; unset, it is pretty on a colour terminal and plain otherwise, and setting it turns the log on unless access_log is False. json writes one object per line with an RFC 3339 UTC time; logger sends each to the hinoki.access logger. access_log_skip (Rust server only) lists paths the log leaves out, such as health checks: exact, or a prefix when the entry ends with *. access_log_slow_ms keeps only answers at least that slow. Both always keep failures (status 400 and up). recent_requests (Rust server only) is a file that also receives each record as JSON, for hinoki mcp's recent_requests tool. server_timing (Rust server only) adds a Server-Timing header with the time taken and the serving lane: unset means in hinoki dev only. sighup (Rust server only; hinoki serve, where the system has SIGHUP) says what the signal does: "reload", which is also what unset means, replaces the workers one at a time with new processes that import the code and read the settings again, "stop" stops the server. max_connections, header_read_timeout, body_read_timeout, write_timeout, native_dispatch and access_log_format, access_log_skip and access_log_slow_ms belong to the Rust server (None keeps its default). hinoki serve refuses a setting the chosen server cannot honour. tls_cert_file and tls_key_file (PEM files, set together) serve HTTPS on either server; http2 adds HTTP/2 to it (ALPN h2, TLS only, off by default). native_dispatch (unset means on) lets the Rust server run the async def handlers it can prove safe without an asyncio task; False keeps every handler in one.

hinoki.settings.CompressionSettings dataclass ¶

CompressionSettings()

Bases: Settings

Response compression, done by Kiso only (it is ignored under another runner, and hinoki serve --server granian refuses enabled).

Off while enabled is false. encodings lists what the server offers in its order of preference (br, gzip). Bodies known to be smaller than min_size bytes, types outside types (type/subtype, type/* or */*+suffix) and responses with cache-control: no-transform are sent as they are. event_streams also compresses text/event-stream and files compresses file responses. gzip_level is 1 to 9, brotli_quality 0 to 9, and max_concurrent bounds the compressions in progress in one worker: past it, answers go out uncompressed.

hinoki.settings.MetricsSettings dataclass ¶

MetricsSettings()

Bases: Settings

Prometheus metrics, kept and served by Kiso only (they are ignored under another runner, and hinoki serve --server granian refuses listen).

Off while listen is unset. listen is the host:port of a dedicated listener (an IPv6 host goes in brackets) that serves only the exposition at path; it never shares the application's port. A listener off the loopback needs allow (addresses or CIDRs of the peers that may scrape) or a token (the bearer token a scrape sends). buckets are the upper bounds, in seconds, of the duration histogram: 1 to 32 finite values, strictly increasing. With several workers each one writes a snapshot every snapshot_interval seconds and any worker's scrape reports them all, one series per worker label.

hinoki.settings.EmailSettings dataclass ¶

EmailSettings()

Bases: Settings

Outbound email. backend has no default, so production never falls back to the console by accident: smtp delivers, console prints the rendered message (development) and memory keeps it in an outbox (tests).

The SMTP fields apply to smtp only. port defaults to 587 for starttls, 465 for tls and 25 for none; security="none" to a host off the loopback needs allow_insecure. username and password go together; read the password from a *_FILE variable. tls_ca_file adds PEM certificates to the bundled public roots (it does not replace them); certificates are always checked. default_sender is the From address of a message that sets none, and message_id_domain the domain of its Message-ID (default: the domain of default_sender, else helo_name, else localhost). Durations are seconds, more than 0 and at most 3600: timeout bounds one whole send() including the wait for a connection and the retries, and must be at least connect_timeout. With check_on_startup the worker connects and authenticates while starting, and a failure aborts the start. memory_capacity bounds the outbox.
