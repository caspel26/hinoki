hinoki.mail.Message dataclass ¶

Message(
    *,
    to: tuple[Recipient, ...] = (),
    subject: str,
    text: str | None = None,
    html: str | None = None,
    sender: Recipient | None = None,
    cc: tuple[Recipient, ...] = (),
    bcc: tuple[Recipient, ...] = (),
    reply_to: tuple[Recipient, ...] = (),
    attachments: tuple[Attachment, ...] = (),
    headers: tuple[tuple[str, str], ...] = (),
)

One email. text or html (or both) is required, and at least one recipient in to, cc or bcc. bcc is never written in the headers. sender falls back to EmailSettings.default_sender. headers are extra (name, value) pairs; the headers Hinoki writes itself (From, To, Date, Message-ID, ...) are refused.

hinoki.mail.Mailer ¶

Mailer(
    settings: EmailSettings,
    templates: Sequence[TemplateBase] = (),
)

The email resource of one worker: it owns the connection pool of the smtp backend, so create it inside a running worker (EmailModule does) and never at import. aclose refuses later sends and closes the idle connections; call it before the loop ends.

hinoki.mail.EmailModule ¶

EmailModule(

    templates: Sequence[TemplateBase] = (),
)

Bases: Module

Opens a Mailer in each worker's lifespan and provides it (ctx.get(Mailer)); installed automatically by an email: EmailSettings field. With check_on_startup the lifespan connects first and a failure aborts the start.

hinoki.mail.EmailError ¶

EmailError(
    kind: EmailErrorKind,
    *,
    code: int | None = None,
    enhanced_status: str | None = None,
    attempts: int = 0,
    possibly_sent: bool = False,
    field: str | None = None,
    index: int | None = None,
)

Bases: Exception

A message was refused or could not be delivered. str(error) is a fixed sentence for kind plus the position or reply code: never an address, the subject, the body, the server's text or a credential.

code and enhanced_status are the SMTP reply's when one came; attempts the delivery attempts made; field and index where a validation failure is (index is the position in that tuple); possibly_sent is true only when the end of the message was written and no reply came, so the server may have accepted it (do not blindly resend).

Template(

    subject: str,
    html: str,
    text: str | None = None,
    context: type[Schema] | None = None,
    description: str | None = None,
)

Bases: TemplateBase

An email template: a subject, an HTML body and optionally a text body, written in the small template language of docs/email-templates.md.

context= names the Schema the template is written for: its fields are the variables, and every variable and every field is checked when the template is compiled. Without context= the template takes a dict (Context) and only the syntax is checked until it is rendered.

hinoki.mail.TemplateError ¶

TemplateError(
    *,
    template: str,
    problems: Sequence[TemplateProblem],
    truncated: bool = False,
)

Bases: EmailError

A template is invalid or cannot be rendered. kind is always EmailErrorKind.TEMPLATE; problems lists what is wrong (the first is mirrored in reason, field (the part), line, column and variable) and truncated tells that more were found. str(error) names the template, the reason, the part, the position and the variable; never a context value, a recipient or rendered text.

hinoki.mail.TemplateReason ¶

Bases: StrEnum

Why a template was refused: the names the engine reports.

hinoki.mail.TemplateProblem dataclass ¶

TemplateProblem(
    reason: TemplateReason,
    part: str | None = None,
    line: int | None = None,
    column: int | None = None,
    variable: str | None = None,
)

One thing wrong with a template. part is "subject", "text" or "html"; line and column (from 1) point into that part of the template source; variable is a name from the template or the Schema, never a value of the context.
