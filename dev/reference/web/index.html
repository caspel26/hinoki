Core API: application, routing and HTTP¶

hinoki.app.Hinoki ¶

A Hinoki application.

Registering routes builds the native router; nothing connects to anything, so factories returning Hinoki are safe to import and call. The instance is itself an ASGI callable (granian --interface asgi module:app); the first call freezes the declarations.

include ¶

Register decorated functions, API subclasses and objects that expose an api() (the admin). Lists and tuples of those are flattened, so a feature package can export one routes list, and Mount(prefix, ...) places a feature under a path chosen here.

hinoki.routing.RouteGroup ¶

A function-based route group with a shared path prefix and defaults.

Decorated functions belong to this group and the group can be included once in a Hinoki application. Use API for class-based resources.

tasks = RouteGroup("/tasks", access=member_only, atomic=True,
                   errors=(NotFound,))

@tasks.get("/")                      # GET /tasks
async def listing(...): ...

@tasks.post("/", status=201)         # POST /tasks, transaction=True
async def create(...): ...

@tasks.get("/health", access=None)   # public on purpose, overriding the group

prefix is prepended to every path ("/" means the prefix itself), access is the default policy (pass access=None on an action to make it public), atomic=True makes POST/PUT/PATCH/DELETE transactional unless the action says transaction=False, and errors are added to each action's own. The result is an ordinary action: rules, OpenAPI and the MCP see no difference.

hinoki.routing.Mount ¶

Places routes under a path prefix chosen where the application is declared.

Hinoki(include=[
    health,
    Mount("/tasks", tasks.routes),
    Mount("/billing", billing.routes),
])

The feature keeps paths relative to itself (/ and /{id}) and the root declaration shows where each feature lives. Items are anything include accepts, including lists and other mounts; prefixes join outside in.

hinoki.access.Access dataclass ¶

Which provider authenticates an action and which permissions it requires.

Access(auth=tokens, permissions=["posts:write"]).

Declaring an Access does not protect anything by itself: only actions that name it are protected. Enforcement belongs to the request pipeline.
