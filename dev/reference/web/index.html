Core API: application, routing and HTTP¶

Updated November 20, 2026 19 min read

from hinoki import Hinoki, RouteGroup, Mount, http, errors and from hinoki.project import manifest_routes. Guides: function-based APIs, class-based APIs, register routes, errors.

hinoki.app.Hinoki ¶

Hinoki(
    *,
    settings: object | None = None,
    include: Sequence[Includable] | None = None,
    modules: Sequence[Module | type[Module]] = (),
    commands: Sequence[Command | type[Command]] = (),
    on_startup: Sequence[Hook] = (),
    on_shutdown: Sequence[Hook] = (),
    startup_url: str | None = None,
    runtime: RuntimeConfig | None = None,
    title: str | None = None,
    version: str | None = None,
    openapi_url: str | Unset | None = UNSET,
    docs_url: str | Unset | None = UNSET,
    redoc_url: str | Unset | None = UNSET,
    rules: RuleSet | None = None,
    enforce_rules: bool = True,
    waivers: str | Path | None = None,
    parsers: Sequence[Parser] | None = None,
    renderers: Sequence[Renderer] | None = None,
    middleware: Sequence[Middleware] = (),
)

A Hinoki application.

Registering routes builds the native router; nothing connects to anything, so factories returning Hinoki are safe to import and call. The instance is itself an ASGI callable (granian --interface asgi module:app); the first call freezes the declarations.

on_startup and on_shutdown list functions taking the worker's ModuleContext (async def or def). Startup hooks run once per worker after the modules have started; shutdown hooks run before they are closed, and only after a startup that completed.

startup_url optionally reserves a public GET/HEAD endpoint that returns {"status": "ok"} after worker startup. It reports startup completion, not application, database, or event-loop health.

waivers names the owner's waiver file applied to the startup rules; it must exist. Without it, hinoki-rules.toml at the project root is used.

enforce() -> None

error_handler ¶

error_handler(kind: type[Exception]) -> ErrorRegistrar

Decorator: answer kind with a function of the exception that returns the APIError to send. It returns the function unchanged.

def card_error(error: stripe.CardError) -> errors.APIError:
    return errors.APIError(error.user_message, status=402)

hinoki.routing.RouteGroup ¶

RouteGroup(
    prefix: str = "",
    *,
    access: Access | None = None,
    atomic: bool = False,
    errors: Sequence[type[APIError]] = (),
)

A function-based route group with a shared path prefix and defaults.

Decorated functions belong to this group and the group can be included once in a Hinoki application. Use API for class-based resources.

tasks = RouteGroup("/tasks", access=member_only, atomic=True,
                   errors=(NotFound,))

@tasks.get("/")                      # GET /tasks
async def listing(...): ...

@tasks.post("/", status=201)         # POST /tasks, atomic=True
async def create(...): ...

@tasks.get("/health", access=None)   # public on purpose, overriding the group

prefix is prepended to every path ("/" means the prefix itself), access is the default policy (pass access=None on an action to make it public), atomic=True makes POST/PUT/PATCH/DELETE transactional unless the action says atomic=False, and errors are added to each action's own. The result is an ordinary action: rules, OpenAPI and the MCP see no difference.

hinoki.routing.Mount ¶

Mount(prefix: str, *items: object)

Places routes under a path prefix chosen where the application is declared.

Hinoki(include=[
    health,
    Mount("/tasks", tasks.routes),
    Mount("/billing", billing.routes),
])

The feature keeps paths relative to itself (/ and /{id}) and the root declaration shows where each feature lives. Items are anything include accepts, including lists and other mounts; prefixes join outside in.

hinoki.project.manifest_routes ¶

manifest_routes(
    start: Path | None = None,
) -> list[Includable]

The routes hinoki.toml declares: the project's, then each app's at its prefix, for Hinoki(include=manifest_routes()).

The manifest is found from start, by default the directory of the calling file (the working directory when the caller has no file), upwards. Outside a project this raises ProjectError.

For model-backed route generation, see Generate CRUD routes and the CRUD API reference.
