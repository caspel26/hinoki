3.4 · Guides

Model options¶

Options that describe a model beyond its columns are decorators, read top to bottom like action decorators. There is no nested class Meta; only names stay class keywords.

# notes/apps/billing/models.py
from datetime import datetime
from uuid import UUID, uuid4

from hinoki import db
from hinoki.orm import Model, OnDelete, field, foreign_key, pk
from hinoki.utils import utc_now

from .customers import Customer


@db.unique("customer_id", "reference")
@db.indexed("customer_id", "created_at")
@db.ordered_by("-created_at", "-id")
@db.timestamps()
class Quote(Model, label="Quote", plural="Quotes"):
    id: UUID = pk(default_factory=uuid4)
    customer_id: UUID = foreign_key(
        Customer, on_delete=OnDelete.RESTRICT, related_name="quotes"
    )
    reference: str = field(max_length=40)
    created_at: datetime = field(default_factory=utc_now)
    updated_at: datetime = field(default_factory=utc_now)
Option Form Effect
single-column index field(index=True) CREATE INDEX on one column
composite or foreign-key index @db.indexed("a", "b") CREATE INDEX on the columns, in order
composite uniqueness @db.unique("a", "b", name=None) UNIQUE (a, b), named with name=; one column uses field(unique=True)
default order @db.ordered_by("-created_at", "id") order of queries without order_by; - is descending
update timestamp @db.timestamps() refreshes updated_at on every ORM update
table name @db.table("quotes") (optional) replaces the derived <app>_<models> name
app part of the name app="sales" (class keyword, optional) replaces <app>; ignored with an explicit table
display names label=, plural= (class keywords, optional) replace the derived singular and plural

Every option decorator is reached through from hinoki import db. The same objects are also importable from hinoki.orm, which keeps older imports such as from hinoki.orm import unique, timestamps working.

Composite uniqueness¶

@db.unique("a", "b") adds UNIQUE (a, b) to the table; it needs two or more distinct columns. A single column uses field(unique=True).

@db.unique("customer_id", "reference", name="uq_quotes_customer_reference")
class Quote(Model):
    id: UUID = pk(default_factory=uuid4)
    customer_id: UUID = foreign_key(Customer, on_delete=OnDelete.RESTRICT)
    reference: str = field(max_length=40)
  • Without name= the backend names the constraint. With it, the migration renders CONSTRAINT "uq_quotes_customer_reference" UNIQUE (...) on PostgreSQL, SQLite, MySQL and MariaDB, so the constraint keeps a stable, chosen name in the database.
  • A name is a letter or underscore followed by up to 62 letters, digits or underscores, compared without case (as MySQL and MariaDB do). Planning refuses a name already used by another constraint, a table, or an index or foreign key that Hinoki names, among the planned models and, in a project with hinoki.toml, in every app.
  • Only a table model can name a constraint: on an abstract model name= raises RegistrationError, because every table inheriting it would repeat the name. Unnamed constraints are inherited as usual.
  • Changing the constraints or their names on an existing table is not planned on PostgreSQL, MySQL or MariaDB (write that migration by hand). SQLite rebuilds the table; a rename alone is not destructive, while changed columns are reported as destructive because existing rows may violate them.

Indexes¶

Use field(index=True) for one ordinary column and @db.indexed(...) for a composite index. A foreign_key has no index= option: index it with @db.indexed("customer_id"), or with a composite index that starts with it. The optional HNK-DB-002 rule (Models.require_foreign_key_index) checks this.

  • index= takes True or False; a primary key or unique column is already indexed and refuses index=True.
  • field(index=True) and @db.indexed("column") on the same column produce one index.
  • Names are ix_<table>_<columns>_<digest>, cut to the backend limit (63 bytes on PostgreSQL, 64 on MySQL and MariaDB); the digest keeps indexed("a_b") and indexed("a", "b") apart.
  • Adding or removing an index is a non-destructive migration.

Default order¶

@db.ordered_by(...) orders every query that has no order_by, lists and pages included. An explicit order_by replaces it; counts and bulk updates ignore it. End with a unique column ("-id") so pages are stable.

Update timestamps¶

@db.timestamps() sets a declared, non-nullable updated_at: datetime on every ORM update statement, including asave and abulk_update. @db.timestamps("modified_at", clock=my_clock) names another column or injects a clock. The parentheses are required: a bare @db.timestamps raises RegistrationError. See utilities.

Names¶

Leave the table name derived for new models. Pin it with @db.table(...) when the model has migration history and its class or module may change: a changed derived name is planned as a guarded drop and create, never a rename. Naming the table twice with different names (@db.table twice, or with table=) is an error naming both. Use label=/plural= for irregular or localized nouns. See table and display names.

Rules for all options¶

  • Column names are checked when the decorator runs; a typo fails at import with the model and the unknown names.
  • Apply options before the model is used: the migration planner, the query layer and the admin read them from the class.
  • Options of abstract bases are inherited; a decorator on the subclass replaces that kind of option. A table model does not pass its options to a subclass.

Not yet

Partial and expression indexes, and soft delete, are not available.
