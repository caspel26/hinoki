Schemas¶

hinoki.schema.Schema ¶

Base class for schemas.

class PostCreate(Schema): title: str becomes a frozen, keyword-only dataclass. PostCreate.validate(data) checks decoded JSON strictly: no coercion, no unknown keys, and every problem reported with its path.

to_dict ¶

to_dict(*, exclude: Iterable[str] = ()) -> dict[str, Any]

The field values as Python objects (UUID, datetime stay what they are), nested schemas converted too. Fields left UNSET are omitted, so the result is exactly "what the client sent" for a partial update.

from_model classmethod ¶

from_model(row: object, **extra: Any) -> Self

Build this schema from a model instance: every field is read from the attribute of the same name, extra supplies or overrides values (for computed fields). Nested models become nested schemas. A field the row lacks is an error, and an unloaded relation still raises RelationNotLoaded: nothing here does I/O.

dump ¶

dump() -> dict[str, Any]

JSON-compatible form; UNSET fields are omitted. Built in Rust, like the JSON answers themselves.

hinoki.schema.Invalid ¶

Bases: Exception

Raised by a check to refuse a value: a stable code, a readable message and optionally the path it concerns (default: the field the check is attached to, or the object itself).

hinoki.schema.Unset ¶

Type of UNSET: a field that was absent from the input (PATCH).

hinoki.schema.field_check ¶

field_check(*names: str) -> Callable[[F], F]

Mark a method as a check on one or more fields: def ok(self, value).

It runs after the structural validation succeeded, so value already has the declared type, and may read the other fields through self. Raise Invalid(code, message) to refuse; it never changes the value. Checks are synchronous and must not do I/O: a rule that needs the database belongs in an operation, not in a schema.

hinoki.schema.object_check ¶

object_check(function: F) -> F

Mark a method as a check on the whole object: def ok(self). Runs after every field check passed or failed (all problems are reported together).
