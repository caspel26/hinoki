# Generate CRUD routes

`CrudAPI` generates model-backed routes on an ordinary API class. Declare the
model in the class header, set schemas and options as class attributes, and
include the class once in the app. Handwritten `@http.*` methods and mixins can
live beside the generated actions.

```python
from typing import Any

from hinoki import Caller, Hinoki, Schema, http
from hinoki.crud import CrudAPI
from hinoki.orm import QuerySet

from app.models import Post
from app.security import editor


class PostOut(Schema, model=Post):
    ...


class PostCreate(Schema):
    title: str
    slug: str
    body: str


class Posts(CrudAPI, model=Post, path="/posts"):
    read_schema = PostOut
    create_schema = PostCreate
    access = editor
    owner = "author_id"

    def get_queryset(self, principal: Caller[Any] | None) -> QuerySet[Post]:
        return Post.filter(published=True).order_by("-id")

    @http.get("/health")
    async def health(self) -> dict[str, str]:
        return {"status": "ok"}


app = Hinoki(include=[Posts])
```

The generated actions are ordinary API routes, visible to OpenAPI, the
`hinoki routes` command and the route registry. The class is mounted once; no import-time or
global auto-registration occurs. A model's read schema and write schemas must
match its fields. See [Schemas](schemas.md) for model-derived schemas.

## Generated actions

List and retrieve are generated by default. Writes are opt-in:

| Class declaration | Action | Method and path | Success |
| --- | --- | --- | --- |
| Always | `list` | `GET /posts` | Paginated `Page[PostOut]` |
| Always | `retrieve` | `GET /posts/{item_id}` | `PostOut` |
| `create_schema = PostCreate` | `create` | `POST /posts` | `201`, `PostOut` |
| `update_schema = PostPatch` | `update` | `PATCH /posts/{item_id}` | `200`, `PostOut` |
| `deletable = True` | `delete` | `DELETE /posts/{item_id}` | `204`, no body |

Generated writes require `access = ...`, unless `public_writes = True` is set
deliberately. Reads are public by default; `read_access = ...` protects them.
Writes run in a transaction. `pagination` selects the page-number policy for
the generated list route.

## Reuse and customization

CRUD configuration and Python methods compose through normal inheritance.
Subclasses inherit the model and options, override options/hooks, and can set a
new `path=`. A model-derived schema from another model is rejected during class
creation. Mixins can provide reusable decorated routes or hooks.
Class-level `access` and `read_access` apply to generated actions only;
handwritten and inherited decorated methods keep the policy on their own
`@http.*` decorator, so protect those routes explicitly.

Use `get_queryset(principal)` to build the list/detail query. It is a
synchronous query builder and does no I/O. When reads are public, `principal`
is `None`; when `read_access` is set, it is the authenticated `Caller`. Apply
tenant or visibility filters here. `owner` is an independent write safeguard,
not read authorization. Writes are also constrained by this query, primary key
and owner column, including in the mutation statement.

Override `async to_schema(item)` for a response shape that needs loaded
relations; relations are never loaded implicitly. Override
`written_queryset(principal)`
to load response relations after a successful write, independently of filters
that might hide the changed row from subsequent list requests.

Generated write routes call these overridable hooks inside their transaction:

```python
def slug_for(title: str) -> str:
    return title.casefold().replace(" ", "-")


class Posts(CrudAPI, model=Post, path="/posts"):
    read_schema = PostOut
    create_schema = PostCreate
    access = editor
    owner = "author_id"

    async def perform_create(
        self, values: dict[str, Any], principal: Caller[Any]
    ) -> Post:
        values["slug"] = slug_for(str(values["title"]))
        return await super().perform_create(values, principal)
```

`perform_update(item, scoped_queryset, values, principal)` and
`perform_delete(item, scoped_queryset, principal)` receive the target and the
query already limited by visibility, key and ownership. Call `super()` to keep
the default scoped database mutation. Hooks may use transactional database
operations; they do not run after commit, so do not send mail or publish
external events directly from them. Hooks are trusted application code: do not
bypass the supplied scoped queryset with an unscoped model write or raw SQL.
Hinoki checks the persisted item after create/update for model identity and
server-assigned field invariants, but cannot sandbox arbitrary hook side effects.

Replace a generated action with a same-name decorated method, or use
`replaces=Crud.CREATE` (or another `Crud` member) on a differently named route.
An undecorated method named `list`, `retrieve`, `create`, `update` or `delete`
intentionally shadows and removes that generated route. A differently named
method without `replaces=` is a separate route and may collide by path/method;
route registration reports duplicates.

## Security and validation

Set `owner = "author_id"` to assign that column from the authenticated caller
on create and constrain update/delete. `identity_key` extracts the owner value
from `Caller.user`; its default reads `.id`. `assign` maps additional
server-owned columns to functions of the caller's user object. Client schemas
cannot accept server-assigned fields. Generated writes require an access
policy even when `owner` is configured.

At class declaration Hinoki rejects abstract models, unknown schema fields,
unsafe nullable fields, missing required create values, update schemas that
can overwrite omitted fields, primary-key updates, unknown assigned columns,
and incompatible derived schemas. `only=` and `exclude=` schemas remain
subject to these same checks.

## Existing `Resource` declarations

Existing pre-alpha `Resource(...)` configurations remain accepted for
compatibility. Their `queryset=` callback is not caller-aware; `perform_*`
hooks are available on those API subclasses too. For response relations after
a write that becomes hidden by the old queryset, its fallback read cannot
preserve eager-loads. Migrate to the class declaration and override
`written_queryset(principal)` when the response needs relations. Existing
`output=` schemas may contain computed fields; class-based schemas may do the
same through `to_schema`.

## OpenAPI and inspection

To inspect routes without starting the server:

```sh
hinoki routes examples.blog.main:create_app --path /posts
```

Generated routes include schemas, access policies, status codes and pagination
in the OpenAPI document. See the [CRUD API reference](reference/crud.md).

Generated CRUD suits ordinary model-backed operations. Prefer a handwritten
action when a workflow has distinct state transitions, error semantics or
side-effects beyond the single model mutation.
