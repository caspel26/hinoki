# Generate CRUD routes

`hinoki.crud.CrudAPI` can add ordinary HTTP routes to an API class from a model
and its input/output `Schema` classes. This is optional: handwritten endpoints
remain normal functions, and generated actions can be replaced individually.
The Blog example uses this for editor-only create/delete while keeping its
filtered list and detail routes handwritten in
[`examples/blog/api.py`](https://github.com/caspel26/hinoki/blob/main/examples/blog/api.py).

## Choose the generated actions

`Resource` always describes a model and its read schema. List and retrieve are
generated by default. Write actions are opt-in:

| `Resource` option | Generated action | Method and path | Success |
| --- | --- | --- | --- |
| Always | `list` | `GET /posts` | Paginated `Page[PostOut]` |
| Always | `retrieve` | `GET /posts/{item_id}` | `PostOut` |
| `create=PostCreate` | `create` | `POST /posts` | `201`, `PostOut` |
| `update=PostPatch` | `update` | `PATCH /posts/{item_id}` | `200`, `PostOut` |
| `deletable=True` | `delete` | `DELETE /posts/{item_id}` | `204`, no body |

Generated write actions require an `Access` policy in `access=`. Setting
`public_writes=True` deliberately makes them public; use that only when public
writes are part of the API contract. Reads are public by default and can be
protected separately with `read_access=`. Writes run in a transaction.

## A working example

This example uses the Blog model and schemas. Its author column is assigned
from the authenticated caller, and its `output` loads the author explicitly
before building the response schema:

```python
from hinoki import Schema, derive
from examples.blog.models import Post
from examples.blog.schemas import PostCreate, PostOut
from examples.blog.security import editor
from hinoki.crud import CrudAPI, Resource
from hinoki.orm import QuerySet


@derive(only=("title", "slug", "body"), partial=True)
class PostPatch(Schema, model=Post):
    ...


def all_with_author() -> QuerySet[Post]:
    return Post.all().select_related("author")


def to_out(post: Post) -> PostOut:
    return PostOut.from_model(post, author_name=post.author.name)


POSTS = Resource(
    model=Post,
    read=PostOut,
    create=PostCreate,
    update=PostPatch,
    deletable=True,
    access=editor,
    owner="author_id",
    queryset=all_with_author,
    output=to_out,
)


class Posts(CrudAPI, path="/posts", resource=POSTS):
    pass
```

This class generates all five actions from the options above. In the checked-in
Blog app, the resource omits `update` and the class replaces `list` and
`retrieve` with filtered handwritten methods; generated `create` and `delete`
remain. Include `Posts` in the app's `include=` list to register the routes. The full application also adds a custom publish action. `replaces=`
names one generated action, so it does not create a duplicate route. A method
named `list`, `retrieve`, `create`, `update` or `delete` also overrides the
matching generated action. See the complete
[`examples/blog/api.py`](https://github.com/caspel26/hinoki/blob/main/examples/blog/api.py).

## Input, ownership and query scope

`read` is the output shape. `create` and `update` are input schemas, not model
classes. Create fields must satisfy required model columns. Update fields must
default to `UNSET`, so omitted fields are left unchanged; the primary key cannot
be updated. Schema fields must match model columns and cannot accept values for
columns assigned by the server.

Use `owner="author_id"` when a model column holds the authenticated user's
identity. Hinoki assigns that column on create and includes it in update/delete
conditions. `identity_key=` extracts the owner value from `Caller.user`; the default is its
`id` attribute. `assign={...}` supplies other server-owned
columns from the caller; client input cannot set either kind of assigned value.
Write access is still required: an owner column is row scoping, not an
authentication policy by itself.

`queryset=` can provide a base `QuerySet` for list/retrieve and scoped changes.
It does not grant access; use `access=`, `read_access=` and `owner=` for
authorization. `output=` converts a row to its read schema when a direct field
copy is insufficient, such as when the response includes a loaded relation.
Relations are never fetched lazily. `pagination=` chooses the page-number
policy for the generated list action; the default is `PageNumberPagination()`.

## OpenAPI and inspection

Generated routes are registered as ordinary actions. They appear in
`hinoki routes`, OpenAPI and the app's route registry, including their schemas,
access policy, success status and pagination. To inspect the Blog routes without
starting the server:

```sh
hinoki routes examples.blog.main:create_app --path /posts
```

The generated actions have stable names (`list`, `retrieve`, `create`,
`update`, `delete`). Use `replaces="list"` (or another name) when a handwritten
method in the same API class needs to supply one action with different filtering
or behavior. See the [CRUD API reference](reference/crud.md) for signatures.

Generated CRUD is a convenience for ordinary model-backed routes, not a
substitute for domain operations. Write a handwritten action when the operation
has workflow rules, distinct error semantics, or side effects beyond a single
model change.
