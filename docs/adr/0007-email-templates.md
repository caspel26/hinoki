# ADR 0007 — Email templates in a small fixed language, rendered in Rust

Status: Accepted · 2026-11-30

**Context.** Applications build the same few messages again and again. Building `subject`, `text` and `html` with string formatting by hand escapes nothing, lets a value with a line break reach a header, and finds a misspelled variable only when the message is sent. [ADR 0008](0008-outbound-email.md) left templates out. The rule for this project is that the framework owns the request path in Rust, owns its schema interfaces and adds no external validation or template framework.

**Decision.** `hinoki.mail.Template` holds a subject, an HTML body and an optional text body in a language with three constructs: `{{ path }}`, `{% if path %}…{% else %}…{% endif %}` and `{% for name in path %}…{% endfor %}`. There are no expressions, filters, includes, macros or inheritance. The parser, the checker, the renderer, the HTML escaping and the derivation of the text from the HTML are Rust (`crates/mail/src/template`), with fixed limits on sizes, nesting, iterations and output. A template has a context `Schema` (or a plain `dict`); a template with a `Schema` is verified against it when the worker starts, so an unknown variable, an unused field, a secret field or a value of the wrong shape stops the start. Rendering happens before `mail.send`, in one synchronous native call; `Template.message` returns an ordinary `Message`, and `send` is unchanged. Templates are registered explicitly (`Hinoki(email_templates=[...])` or `EmailModule(templates=[...])`) and files are read in the worker's lifespan, never at import. Errors are `TemplateError` (kind `template`) and name the template, part, position and variable, never a value, recipient or rendered text. `hinoki mail check` and `hinoki mail preview` run the same code from the CLI, and the opt-in rule `HNK-MAIL-001` checks templates in `hinoki check`.

**Consequences.** A template cannot compute: a decision such as "show this line when the plan is paid" is made in Python and passed as a field. The text between `{{` or `{%` cannot appear literally. The context crosses the binding as Python objects, copied once per message (bounded by the context limits). A `SecretStr` is refused, so a secret cannot be put in a message through a template. The limits are constants, not settings. There is no translation, no inline image and no registration in `hinoki.toml`.

**Alternatives.** A Rust template crate such as minijinja or Tera (a larger language with filters and expressions that must be sandboxed and that the project would have to keep in step with its own schema checks); Python's `string.Template` (no loops or conditions, no escaping, no early check); Jinja2 (a Python dependency with an expression language and a sandbox to maintain, rendering on the Python side); rendering inside `Mailer.send` (a second message shape across the binding and a preview that depends on a mailer).

**Revisit when** translation, shared layouts or includes are needed, or when applications keep moving logic into context fields only to work around the language.
