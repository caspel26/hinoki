    01 The problem

    Architecture drifts. Hinoki turns each promise into a check.

    • ✕✓

      An endpoint that forgot its access policy is public by default.

      Declare access=; HNK-ACC-001 fails the check when it is missing.

    • ✕✓

      A write that should be atomic is not.

      Declare atomic=True; HNK-TXN-001 reports every state-changing action without it.

    • ✕✓

      A response leaks a token or a whole model.

      HNK-SCH-001 and HNK-API-001 keep named fields out of responses and models out of handlers.

    • ✕✓

      Layers drift: models start importing the API.

      HNK-IMP-001 reads the source files and reports forbidden imports.

    Describe the table

    A model is a typed class. Hinoki compiles its queries for the configured database in the Rust ORM, and nothing touches a database at import.

    04 Included

    What is implemented today.

    Pre-alpha, and exercised in the examples. The status page lists every boundary.

    • Databases

      SQLite, PostgreSQL, MySQL and MariaDB through the Rust ORM, with relations, querysets and reviewed, file-based migrations.

      Databases

    • Sync and async

      Plain def and async def handlers, with bounded execution for the synchronous ones.

      Sync and async

    • Atomic writes

      atomic=True on an action, or db.atomic as a block or a decorator, in sync and async code.

      Transactions

    • Model hooks

      Lifecycle hooks with instance state, and callbacks that run after the commit.

      Models and queries

    • Bulk writes

      bulk_create, bulk_update and bulk_delete, and their abulk_* forms, each in one transaction.

      Models and queries

    • Checked responses

      Every response is checked at runtime against its return annotation. An annotation that cannot be checked stops the app at startup.

      Endpoints

    • Optional admin

      An extra you activate explicitly, with four styles, its own users, a sign-in page and per-model permissions.

      Admin

    • Kiso server

      The default server is Kiso, Hinoki's Rust HTTP server. Granian stays available with --server granian.

      Serving

    • MCP and OpenAPI

      A generated OpenAPI document, a development MCP server and an application MCP server.

      Development MCP

    Used by the Tracker example. Example output: see the Rules guide.

    declaration

    Actions.require_return_type(match, except_)

    A missing return annotation, Any or object is reported; None is fine for a 204. Example output: see the Rules guide.

    declaration

    Actions.require_pagination(match, except_)

    Used by the Tracker example. Example output: see the Rules guide.

    declaration

    Schemas.forbid_exposure("token")

    Used by the Tracker example. Example output: see the Rules guide.

    declaration

    Schemas.require_string_limits()

    A text field passes with max_length, or when it is an Enum or Literal. Example output: see the Rules guide.

    declaration

    Models.require_explicit_table(match)

    Renaming a class then cannot change its physical table. Example output: see the Rules guide.

    declaration

    Models.require_foreign_key_index(match)

    The column must lead an index, a primary key or a unique constraint. Example output: see the Rules guide.

    declaration

    Imports.forbid(
    source="tracker.models", target="tracker.api"
)

    Read from the source files; dynamic imports are reported, not ignored. Example output: see the Rules guide.

    Exceptions live in hinoki-rules.toml, need a reason, an owner and a bounded target, and stay visible as waived.

    06 Fit

    Who it is for, and who it is not for yet.

    A fit today

    • You are evaluating a typed Python API with SQLite, PostgreSQL, MySQL or MariaDB.
    • You want architectural promises that a tool can check, not only review.
    • You can use a source checkout and test against disposable data.

    Not yet

    • Production use: the API and migration format may change.
    • SQL Server or Oracle, which are not supported yet.
    • Workloads that need end-to-end performance claims.
    • Implicit many-to-many relations and advanced relation paths.
