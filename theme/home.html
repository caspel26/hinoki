Single contract

One declaration, every consumer.

Source excerpts from the checked-in Notes and Tracker examples. Routing, validation, OpenAPI, architectural rules and development MCP all read the same typed Python declarations.

examples/notes/notes/apps/notes/models.pylines 9–14
@db.ordered_by("title")
@db.table("notes")
class Note(Model):
    id: UUID = pk(default_factory=uuid4)
    title: str = field(max_length=80, index=True)
    body: str = ""

Read by

Rust ORM
Compiles queries for SQLite, PostgreSQL, MySQL or MariaDB without import-time I/O.
migrations plan
Diffs the model against recorded migration state and writes a reviewed SQL file.
hinoki check
HNK-DB-001 verifies explicit @db.table; HNK-DB-002 verifies indexed foreign keys.
examples/notes/notes/apps/notes/schemas.pylines 15–24
class NoteIn(Schema):
    title: Annotated[str, Field(min_length=1, max_length=80, strip=True)]
    body: Annotated[str, Field(max_length=10_000)] = ""

class NoteOut(Schema):
    id: UUID
    title: str
    body: str

Read by

Rust validator
Strict decoding with no implicit coercion. Errors report every problem in declaration order.
Response check
Every response is verified against its return annotation; only fields named on NoteOut leave the process.
OpenAPI & rules
Emits JSON Schema directly; HNK-SCH-001 forbids sensitive field names; HNK-SCH-002 enforces string limits.

Read by

Access
member_only resolves a bearer token to a Caller[Member] and checks tracker:use before the body is read.
atomic=True
Opens a transaction for the action and rolls it back before translating NotFound or TaskAlreadyDone into an HTTP error.
OpenAPI & rules

{# Card B: Application MCP #}
expose_as_mcp · POST /mcp App MCP

Publish HTTP actions as MCP tools with the exact same security contract.

Each remote MCP tool call dispatches through the app like an HTTP request — preserving authentication, Access policies, strict Schema validation and atomic=True.

notes/main.pyread-only by default
from hinoki.ai.mcpapp import expose_as_mcp

mcp = expose_as_mcp(
    app,
    tools=["notes.apps.billing.api.list_invoices"],
    access=billing_staff,
)
app.include(*mcp)  # mounts POST /mcp
  • GET / HEAD / QUERY only unless allow_writes=True
  • access is mandatory — never bypasses ownership or tenant rules
  • Tool schema & validation derived directly from the OpenAPI operation

Architecture checks

Twelve optional rules. Turn promises into CI checks.

Adopt the rules your codebase cares about in a RuleSet. Every exception lives in hinoki-rules.toml with a reason, owner and expiry date — expired waivers fail CI with HNK-WVR-002.

Rules guide

Declaration

Actions.require_access(match, except_)

Violated

Waived

Declaration

Actions.require_permissions(match, except_)

Flags an action whose Access policy grants entry without naming a concrete permission. Startup check.

Declaration

Actions.require_atomic(methods=("POST", "PUT", "PATCH", "DELETE"))

Violated

tests/projects/rulesapp.py:12: HNK-TXN-001 [violated] POST /items (create) does not declare atomic=True

Declaration

Actions.forbid_model_response(match)

Prevents ORM models from leaking database columns into HTTP responses. Return a Schema instead.

Declaration

Actions.require_response_annotation(match)

Every matched action must annotate a concrete return type so response verification and OpenAPI stay exact.

Declaration

Actions.require_pagination(match, except_)

Flags unbounded list responses on GET actions so every collection endpoint returns a Page.

Declaration

Schemas.forbid_fields("password_hash", "secret")

Blocks sensitive field names from ever appearing on a response Schema.

Declaration

Schemas.require_max_length(match)

Ensures every text field on a request Schema bounds input length with Field(max_length=...).

Declaration

Models.require_explicit_table()

Requires @db.table("...") so refactoring a Python class name never renames a database table.

Declaration

Models.require_fk_index()

Verifies every foreign-key column declares an index before migrations are generated.

Declaration

Imports.forbid(source="apps.billing", target="apps.shipping")

Static AST check. Parses source files without importing the application and rejects forbidden module boundaries.

Declaration

EmailTemplatesMatch()

Static template check. Compiles registered email templates against their typed context Schema and flags unknown variables or invalid filters before deploy.

{# ----- 05 · RUNTIME INVARIANTS (ELEVATED BENTO CARDS) ----- #}
05

Runtime invariants

Guarantees enforced by the framework.

Implemented today and exercised in the test suite. Every boundary and limitation is tracked on the status page.

  • {{ m.icon("plug") }}01 · import

    Nothing touches a database at import

    Importing models, schemas or an application performs no I/O and opens no connections. Pools are created on the worker lifespan and closed on graceful shutdown.

    verified in testsApplication modules →
  • {{ m.icon("shield-check") }}02 · access · atomic

    Policy and transaction on the decorator

    access= gates the action before the body is read; atomic=True rolls back before translating an HTTP error.

    verified in testsTransactions →
  • {{ m.icon("braces") }}03 · schema

    Strict validation, no coercion

    Compiled once per Schema in Rust. Unexpected types fail with structured 422 diagnostics instead of silent casting.

    verified in testsValidate input →
  • {{ m.icon("database") }}04 · migrations

    SQL you review; startup never changes tables

    hinoki migrations plan writes SQL files you inspect for SQLite, PostgreSQL, MySQL and MariaDB. Workers never auto-migrate, and installing Hinoki never mutates a database.

    verified in testsMigrations →
  • {{ m.icon("circle-check") }}05 · response

    Every response checked against its annotation

    Return values are verified against the action's annotation; with atomic=True a mismatch rolls the write back. An annotation that cannot be checked stops the app at startup.

    verified in testsRequests and responses →
  • {{ m.icon("server") }}06 · lifecycle

    Bounded sync executor, graceful shutdown

    Plain def and async def handlers coexist with bounded queues, executor pools, timeouts and a clean drain.

    verified in testsSync and async code →
{# ----- 06 · PRE-ALPHA SCOPE ----- #}
06

Pre-alpha scope

What's ready today and what's not there yet.

Hinoki is pre-alpha. Public APIs and migration formats can still change; the status page tracks every boundary.

A fit today

  • Evaluating a typed Python API with Kiso and SQLite, PostgreSQL, MySQL or MariaDB.
  • Turning architectural promises into automated CI checks with hinoki check.
  • Building with coding agents via hinoki mcp, AGENTS.md and expose_as_mcp.
  • Using the optional admin, OpenAPI diffing and reviewed SQL migrations.

Not yet

  • Production deployments: public APIs and migration state format may still change.
  • PyPI distribution: not published yet; the hinoki name on PyPI is unrelated.
  • Container images or built-in health routes: you bring your own deployment wrapper.
  • SQL Server, Oracle, or implicit many-to-many relations.
